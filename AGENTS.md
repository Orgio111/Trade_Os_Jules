## 1. Mission & Core Architectural Invariants (NON-NEGOTIABLE)

Every AI coding agent (Google Jules, Gemini CLI, OpenRouter Coding Agent) operating in this repository MUST strictly enforce the following invariants. Any Pull Request violating these rules is invalid:

1. **100% Isolation of `svc-risk-exec` (Rust):**
   - `services/risk_exec_rust/` MUST NEVER import, link, or call any LLM SDK, MCP server, or prompt orchestrator.
   - No AI agent, CLI command, or external HTTP request may alter the 8 risk parameters defined in `risk_config.json`.
   - Model updates into `svc-risk-exec` are ONLY permitted via `POST /internal/hotswap` after verifying the `.onnx` file's SHA-256 digest and atomically swapping the active pointer via `arc-swap` (`ArcSwap`), while retaining the previous model path/version for instant rollback.
2. **Zero LLMs in the Live Trading Execution Path:**
   - Real-time signal filtering, strategy selection, and regime drift detection may ONLY use the 4 lightweight ML models:
     1. **LightGBM (`ONNX Runtime` in Rust, `< 1 ms`)**
     2. **Vowpal Wabbit (`--cb_explore_adf` Contextual Bandit, `~1 ms`)**
     3. **TimesFM 2.5 (`google/timesfm-2.5-200m-pytorch`, `~86–450 ms`)** — MUST execute strictly on `1m / 5m / 15m / 1h` candle-close events, NEVER on every tick.
     4. **River (`river.drift.ADWIN`, `< 1 ms`)**
3. **Strict Local Memory Budget (`< 1 GB RAM`):**
   - Do NOT introduce PostgreSQL, MySQL, Redis, RabbitMQ, Kafka, or Electron.
   - Hot storage (`0–24h`) uses local **DuckDB** (`data/hot/live_state.duckdb`); Cold storage (`>= 24h`) offloads ZSTD-compressed `.parquet` files to Google Drive (`data/archive_queue/`).
   - Heavy multi-thousand strategy sweeps (`VectorBT`) and monthly `Unsloth` 4-bit QLoRA fine-tuning run exclusively on Google Colab T4 GPU via `notebooks/`—never on local CPU/RAM.
4. **Tokenizer Engine Mandate (`mini_hermes_rust`):**
   - Use ONLY `huggingface/tokenizers` (`tokenizers` Rust crate loading `tokenizer.json`) for local 0 ms token counting.
   - Do NOT use `tiktoken` or `tiktoken-rs`.
   - Apply a `+15%` safety buffer when estimating token budgets for closed-source APIs (Gemini, Claude).
5. **Pre-Train Codegen Sandbox Gate:**
   - Any training script generated by an LLM (`train_candidate.py`) MUST pass: (a) Python `ast.parse()` syntax validation, (b) a 5-second dry-run on 100 synthetic rows, and (c) verified `.onnx` export before touching real datasets or live pipelines.

3. Detailed Component Specifications
3.1 svc-data-hub (Go — Port 8081) & DuckDB Schema
Dependencies: Go 1.22+, github.com/gorilla/websocket, github.com/marcboeker/go-duckdb (CGO enabled in Dockerfile).

Timestamp & Staleness: Convert all exchange timestamps to UTC milliseconds (int64). If now_utc_ms - event_utc_ms > 5000, set stale_flag = true.

Database Schema (data/hot/live_state.duckdb): Must initialize these exact 6 tables on startup:

market_candles (symbol VARCHAR, timeframe VARCHAR, ts_utc BIGINT, open DOUBLE, high DOUBLE, low DOUBLE, close DOUBLE, volume DOUBLE, spread DOUBLE, atr_14 DOUBLE, timesfm_pred DOUBLE, regime_tag VARCHAR)

trade_memory (trade_id VARCHAR PRIMARY KEY, strategy_id VARCHAR, strategy_version VARCHAR, symbol VARCHAR, timeframe VARCHAR, entry_time BIGINT, exit_time BIGINT, entry_price DOUBLE, exit_price DOUBLE, position_size DOUBLE, slippage DOUBLE, commission DOUBLE, pnl_net DOUBLE, mae DOUBLE, mfe DOUBLE, exit_reason VARCHAR, hypothesis VARCHAR, market_context_json VARCHAR, decision VARCHAR, tags VARCHAR, context_embedding VARCHAR)

experiments (experiment_id VARCHAR PRIMARY KEY, strategy_template VARCHAR, params_json VARCHAR, dataset_range VARCHAR, is_sharpe DOUBLE, oos_sharpe DOUBLE, wf_consistency DOUBLE, max_dd DOUBLE, profit_factor DOUBLE, total_trades INTEGER, status VARCHAR)

strategy_registry (version_id VARCHAR PRIMARY KEY, git_commit_sha VARCHAR, onnx_model_path VARCHAR, onnx_sha256 VARCHAR, parent_version VARCHAR, status VARCHAR, deployed_at BIGINT)

orders_audit (order_id VARCHAR PRIMARY KEY, strategy_version VARCHAR, symbol VARCHAR, side VARCHAR, qty DOUBLE, expected_price DOUBLE, fill_price DOUBLE, slippage_bps DOUBLE, lifecycle_state VARCHAR, risk_check_reason VARCHAR)

system_alerts (alert_id VARCHAR PRIMARY KEY, severity VARCHAR, category VARCHAR, message VARCHAR, resolved BOOLEAN)

3.2 svc-risk-exec (Rust — Port 8082)
8 Mandatory Risk Rules (risk_config.json):

max_position_size_risk = 0.01 (1% max risk per trade)

max_exposure_per_instrument = 0.20 (20% max capital per symbol)

max_sector_exposure = 0.40 (40% max sector/asset-class exposure)

max_correlation_limit = 0.70 (block concurrent exposure if pairwise correlation > 0.70)

daily_loss_limit = 0.03 (3% daily realized+unrealized loss locks trading until next UTC day)

max_drawdown_limit = 0.10 (10% peak-to-trough drawdown triggers global halt)

max_order_price_deviation = 0.01 (1% max deviation from latest verified reference price)

require_fresh_data = true (reject if stale_flag == true or age > 5000ms), duplicate_order_cooldown_sec = 30, kill_switch boolean, and session_filter (allowed UTC trading windows).

Order Lifecycle State Machine: Every order transitions strictly through Submitted -> Accepted -> PartiallyFilled -> Filled -> Closed (or Rejected), writing every state change and risk_check_reason to orders_audit.

8 Auto-Rollback & Telegram Alert Triggers:

Daily loss >= 3%

Drawdown velocity > 2x normal threshold

Execution slippage > 2x modeled slippage

Exchange/Risk Order Rejected

Market data disconnected / stale feed (> 5s)

River ADWIN drift alert (POST /internal/drift_alert)

Hard risk rule breach attempt

Telegram /kill command received

3.3 svc-trainer & Research Pipeline (Python 3.11+)
2-Stage Pruning & 6-Gate Validation (run_sweep.py):

Seed Templates: Warren Buffett (Value: ROE > 15%, D/E < 0.5, FCF > 0, Margin of Safety 20–40%), Peter Lynch (Growth: PEG < 1, CAGR > 15%), Ray Dalio (All-Weather + 4 Macro Quadrants), George Soros (Reflexivity: SMA50 + Volume + Sentiment), Jim Simons (Mean Reversion ±2% MA20 + cross-asset rank).

Stage 1: Run 5,000–50,000 parameter combinations via VectorBT on the last 3 months of data; drop bottom 90%.

Stage 2 (6 Gates):

In-Sample (60%): Profit Factor >= 1.35, Trades >= 200, net positive after commission + spread + slippage + financing.

Out-of-Sample (20%): OOS Sharpe >= 0.60 * IS Sharpe.

Walk-Forward (5 windows): >= 4/5 windows profitable.

Parameter Sensitivity Heatmap: Broad stable plateau across ±10–20% parameter perturbations (reject isolated sharp peaks).

Bias, Distribution & Monte Carlo (20%): 1,000 simulations with 95% staying inside Max DD limit, 0 look-ahead/survivorship/leakage bias, VaR/CVaR/Skewness check, and Sharpe > Buy & Hold.

Paper Trading Readiness (4–12 weeks): Execution slippage within ±15% of backtest assumptions.

Shadow Gate (lgbm_incremental.py): Retrain LightGBM via init_model/refit every 50 trades or at 00:00 UTC, export .onnx via onnxmltools, shadow-score alongside the live model for 20–30 signals, and call POST /internal/hotswap ONLY if Shadow score outperforms Live.

3.4 mini_hermes_rust (~10–25 MB RAM)
Token & Context Management (tokenizer.rs):

Load local tokenizer.json via tokenizers crate (+15% buffer for closed APIs).

4 Token Savers: (1) max_budget = 2,000 token pre-flight truncation, (2) 300–500 token RAG chunking of trade_memory (top-3 retrieval), (3) overflow guard preventing failed retry loops, (4) JSON-to-CSV/compact key minification.

4 Context Window Guards: (1) Replace large tool outputs with 1-line summaries post-analysis, (2) Sliding window retaining System Prompt + last 4–6 messages, (3) Rolling compaction at 75% capacity into a 5–10 sentence summary, (4) State offload to trade_memory followed by context reset.

1 LLM = 15 Role Prompt Orchestrator: Cycles a single configured LLM endpoint (OpenRouter, NVIDIA NIM, or local Ollama phi3:mini/llama3:8b) through 15 specialized system prompts: Scout, News, Sentiment, Regime, Trend, MeanRev, Vol, Quant, Session, Event, Exit, Coding, Critic/QA, Portfolio, Decision.

MCP & Trading Skills: Integrate tradesdontlie/tradingview-mcp (Chrome DevTools Protocol port 9222), OpenBB, Jakeschincariol/day-trader-skill, tradermonty/claude-trading-skills, and agiprolabs/claude-trading-skills.

4. Coding Standards & Error Handling
Rust: Use thiserror / anyhow for error propagation. Never call .unwrap() or .expect() on network responses, JSON parsing, or market data channels in production code. Use rustls-tls for reqwest to avoid OpenSSL cross-compilation issues in Docker.

Go: Always wrap DuckDB writes in a sync.Mutex (DuckDB single-process write lock safety) and handle WebSocket disconnects with exponential backoff reconnection.

Python: Use polars and duckdb for zero-copy/low-RAM data operations instead of loading multi-gigabyte DataFrames into pandas locally.

Secrets: Never hardcode API keys, Telegram tokens, or local file paths. Read all configuration from .env with safe defaults.
